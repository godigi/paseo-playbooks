# Pausing a run

Status: Accepted

## Context

Sometimes a run must hold still without being thrown away: a step is going the wrong way,
the human wants to look at the PR before more work lands, or a shared resource is busy.
Cancel ends the run for good. There was no way to stop new work and pick up later.

A workspace has at most one active run, so a workspace-wide pause would do the same as
pausing that run.

## Decision

- An active run can be paused and resumed from its chevron menu in the panel, next to
  Cancel. There is no workspace-wide or header button.
- Pausing drains the run instead of interrupting it. Running step agents finish their
  current turn and their reports are recorded. No new work starts: `start_step` is refused,
  and so are the manager's `nudge_step` and the panel's Retry. Timeouts keep running.
- While the run is paused, manager wake-ups stay in the run's inbox. A manager that is busy
  when the pause happens gets one steer message telling it to stop starting steps; an idle
  one is not woken.
- Resuming wakes the manager with a resume note, the ready steps and the wake-ups held
  during the pause.
- Run state gains `pausedAt` (null when not paused). The run's `status` is unchanged, so
  existing status checks are unaffected. The panel shows "· paused" and stops pulsing the
  run's dot; `get_run` returns `paused`. History records `run_paused` and `run_resumed`.
- A paused run is skipped when `concurrency` slots are handed out, so it does not take a
  slot it cannot use. Slots it already holds stay held.
- Canceling or failing the run clears the pause, and so does starting a manual after-task.
  A pause left on a run that has since ended means nothing.
- Gates can still be decided while the run is paused. Their transitions apply, and the
  manager hears about them on resume.

## Consequences

- Pause is safe: no step is cut off in the middle of an edit or a push. It is not
  immediate, because running steps finish their turn first. To stop at once, cancel the run.
- The manager protocol gains a rule about pauses. There are no new manager tools: pausing
  is a human control.
- Pausing every run of a project at once could come later as a separate decision.
