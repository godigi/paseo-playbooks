# Run names chosen by the Playbook Manager

Status: Accepted

## Context

The panel labels each run's tab with its short id (`653f53`). With several runs of one
playbook side by side, nothing tells them apart without opening each menu. The first text
input is not a reliable label: it is often a long free-text request.

## Decision

- `start_playbook` takes an optional `name`: 2 to 4 words saying what the run is about (e.g.
  `login-redirect-fix`). The manager protocol asks the Playbook Manager to give one.
- The run stores it as `name` (`null` when absent or blank), whitespace collapsed to one line
  and cut to 32 characters. Runs saved before have none.
- A run's tab label is its name, else the first line of its first text input cut to 24
  characters, else its short id. Trains keep their station's name and short id.
- The run's details menu shows its full id, which the tab no longer does.

## Consequences

- Runs read as what they are about, and the label stays short.
- Runs that no manager names (a run created for an existing agent, older runs) fall back
  to their input or id.
- The name is a label only: tools still address runs by id, and names need not be unique.
